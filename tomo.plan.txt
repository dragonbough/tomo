###################
how its gonna work:
###################

data.py | buddy.py | pomodoro.py | app.py | gui.py | tests.py

data.py
- features functions providing communication between program and SQLite database
- passes data into app.py

buddy.py
- manages buddy system using FSMs
- separate module that can be called by main app for buddy functionality

pomodoro.py
- manages pomodoro timer system
- separate module called by main app for pomodoro functionality

app.py 
- receives data from data.py and uses them to fill up backend data structures
- features functions allowing for the retrieval of data structures (e.g tasks, subtasks) and manipulation of data structures 

gui.py
- implements "views" of the data from app.py, within GUI interface in PyQt6

tests.py 
- runs unit tests for each module to ensure there are no bugs

##################
main philosophies: 
##################

DBC -- each module should expect to return something and expect to receive something before doing so (post conditions and pre conditions) -- otherwise, throw errors

error checking -- ANYTIME anything is wrong in the code, make sure it crashes -- complicated systems like these can build up unseen issues which are hard to debug

user-focussed design -- make the interface easy to use and user first -- don't make it convoluted or complicated

intelligent -- the program has to be smart enough to do what the player is thinking it should be able to do at any time
